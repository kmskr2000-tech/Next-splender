# 아트 컨셉 검토: 그래픽 스타일 · 화면 방향

작성: 아트팀 / 상태: 제안(디렉터 검토 대기) / 대상: 2~4인 멀티플레이 전용 스플렌더류 모바일 게임, 크리처 수집+진화

## 0. 참조작 확인 결과 (pokemon-splendor, 읽기 전용)
- 방향: **세로 전용 설계**. `.phone { max-width: 480px }`, 모바일 우선. 900px 이상 데스크톱에서만 2열(보드 | 내 상태) 전환. 가로 모바일 전용 레이아웃·orientation 처리 없음.
- 도트: `img { image-rendering: pixelated }`. 카드 스프라이트 높이 52px, 도감 56px, 애니메이션은 GIF(`assets/anim`).
- 시사점: 도트는 52px대 소형에서도 읽히지만 이는 원작 IP 인지도 덕이 크다. 신작 오리지널 크리처에는 그대로 적용 불가. 에셋 복사 금지 유지.

## 과제 1. 그래픽 스타일 비교

평가: 5점 만점, 높을수록 유리. 제작비/AI 일관성/애니메이션 비용은 "쉬울수록 높음".

| 기준 | A. 도트(픽셀) | B. 2D 치비/카툰 일러스트 | C. 플랫 벡터(두꺼운 외곽선 최소) | D. 3D 렌더풍 2D(클레이/토이) |
|---|---|---|---|---|
| 비게이머 직장인 호감도 | 2.5 (레트로 감성층 한정, 호불호) | **4.5** (캐릭터 수집 앱 문법에 익숙) | 3.5 (깔끔하나 정서 약함) | 4 (귀엽고 고급스러움) |
| 80~90pt 카드 가독성 | 4 (정수배 스케일 시 선명) | 4 (실루엣+굵은 외곽선+채도 대비 필수) | **4.5** (단순 형태) | 3 (질감·그림자가 소형에서 뭉침) |
| 진화 단계 차이 표현 | 3 (격자 한계, 큰 크기 변화 어려움) | **4.5** (크기·장식·표정·오라로 3단계 구분) | 3.5 | 4 |
| 제작비 | **4** (소형, 수정 쉬움) | 3 (장당 렌더 공수 큼) | 4 | 2 |
| AI 생성 일관성 | 2 (격자·팔레트 깨짐, 후보정 필수) | 3.5 (LoRA/스타일 레퍼런스로 가능, 손질 필요) | 3.5 | 3 (재질 편차) |
| 애니메이션 비용 | 3.5 (프레임 수작업) | 3.5 (레이어 분리 후 Spine/Lottie 아이들) | **4.5** (SVG/Lottie 용이) | 2.5 |
| 용량/로딩 | 4.5 | 3.5 (WebP/AVIF로 완화) | **5** | 3 |
| 레퍼런스 성공작 | Stardew, Pokemon 레트로, Vampire Survivors(니치→대중 사례) | Pokemon Masters/Pocket, Monster Hunter Now, Marvel Snap, Hearthstone, Cookie Run | Monument Valley, Alto, Kahoot | Pokemon TCG Pocket(3D 카드), Animal Crossing |
| 합계(대략) | 26 | **30.5** | 28.5 | 24.5 |

### 판단
- 도트: 참조작 반응은 "원작 향수 + 포켓몬 IP"와 분리해서 봐야 함. 오리지널 크리처에는 향수 보너스가 없고, 비게이머에게 "싸 보인다"는 인상 위험.
- 치비/카툰: 대중성과 진화 표현력 최상. 단점은 제작비와 AI 일관성. 완화책은 아래 제작 규칙.
- 플랫 벡터: 보조 UI(토큰, 아이콘, 귀족 타일)에 적합. 크리처 메인으로는 정서 약함.
- 3D풍: 고급스러우나 소형 가독성·비용 불리. 보스/진화 연출 컷에만 선택 사용 검토.

### 추천: **B. 2D 치비/카툰 일러스트 (크리처) + C. 플랫 벡터 (UI/토큰/아이콘) 하이브리드**
핵심 제작 규칙(일관성·성능 확보용):
1. 크리처는 **굵은 단색 외곽선 + 2톤 셀 셰이딩 + 원색 계열 1개 주색**. 속성(토큰 색)과 주색 일치.
2. **실루엣 우선**: 흑백 축소(64px) 상태에서도 3종이 구분돼야 함.
3. 진화 단계 규칙: 1단계 = 둥근 치비 2.5등신 / 2단계 = 비율 늘리고 장식 1개 추가 / 3단계 = 오라·날개·왕관 등 실루엣 확장 + 프레임 테두리 등급 색(색만 의존 금지, 별 1~3개 병기).
4. 카드 표시는 정적 WebP(256x256 원본, 카드 표시 160px 렌더 @2x~3x), 애니메이션은 레이어 분리 후 아이들 루프(Lottie/CSS transform)로 최소화. 상세 연출은 진화 순간에만.
5. AI 도구 파이프라인: 스타일 레퍼런스 시트 1장 고정 + LoRA/스타일 코드 + 크리처별 초안 -> 사람이 외곽선·팔레트 후보정. 팔레트 16색 내외 고정, 후보정 시안 승인 전에는 대량 생성 금지.

### 검증 방법 (착수 전 1주 내 가능)
- 시안: 크리처 3종(1단계/3단계 쌍 = 6장) x 2스타일(B vs 도트) = 12장. 동일 카드 프레임, **실기기 폭 85pt 크기**로 렌더.
- 대상: 비게이머 직장인 20~30명(20~40대, 보드게임/모바일게임 비중 혼합), 게임 앱 설치 경험은 설문 분류.
- 테스트 3종:
  1. 선호도 A/B (블라인드, 순서 랜덤) + 이유 한 줄.
  2. 5초 테스트: 카드 3장을 보여주고 "어느 쪽이 진화한 모습인가/무슨 속성 같은가" 정답률 (가독성·진화 표현력).
  3. "이 게임을 친구에게 보여주겠는가 / 다운로드하겠는가" 5점 척도.
- 합격선(제안): 선호도 B가 60% 이상이면 B 확정. 40~60%면 혼합안 재검토(도트 UI 요소 + 일러스트 크리처 등). 진화 구분 정답률 90% 이상.
- 추가: AI 일관성 점검으로 동일 설정에서 크리처 10종 생성 후 팔레트·외곽선 이탈률을 아트 리뷰.

## 과제 2. 세로 vs 가로

### 정보량 (최대 케이스: 4인)
- 마켓: 3티어 x 4장 = 12장 + 티어별 덱 3
- 토큰 6종 (보석 5 + 와일드) 은행 재고
- 귀족/보너스 타일 3~5장 (4인 시 5장)
- 상대 3명: 점수, 보너스(5색), 보유 토큰, 예약 카드(최대 3)
- 내 상태: 점수, 보너스, 토큰, 예약 카드, 행동 버튼

### 세로 390x844pt 배치 검증
안전영역 가정: 상단 47 + 하단 34 제외, 가용 약 **763pt**.

```

+--------------------------------------+
```

높이 합계(간격 포함): 44+64+52+312(카드3행)+12+52+96+56 = 688 + 구획 간격 약 40 = **약 728pt < 763pt**. 약 35pt 여유로 **가능**. 단 여유가 작아 다음이 필수.
- 카드 폭 80pt(5열: 카드 4 + 덱 1 + 간격 = 약 372pt). 80x104는 카드 내 정보 최소화 필요: 크리처 일러스트, 점수, 비용 칩(색+숫자, 아이콘 형상 병기) 외 텍스트 금지. 상세는 길게 누르기/탭 확대.
- 터치 타겟: 카드 80x104, 토큰 48, 액션 56 모두 44pt 기준 충족. 상대 칩 118x64 충족.
- SE급 소형(375x667, 가용 약 586pt)은 **초과**. 대응: 귀족 줄을 접기(탭 시 펼침), 내 상태 한 줄 압축, 카드 높이 96 축소. 최소 지원 해상도는 디렉터/프로그래밍팀과 확정 필요.
- 대형 기기(430x932)는 여유분을 카드 크기 확대에 할당.

### 상대 정보 위계 해법
1단계 (항상 노출, 칩 118x64): 이름/아바타, 점수(큰 글씨), 보너스 5색 점 + 합계, 토큰 총합, 예약 개수. 차례인 상대는 테두리 강조 + "차례" 텍스트 라벨(색 단독 의존 금지).
2단계 (칩 탭, 하단 시트 약 40% 높이): 보너스/토큰 6종 수치 상세, 예약 카드 (공개 예약만; 비공개는 뒷면 + 티어), 최근 행동 로그.
3단계 (선택): 상대 비교 모드 -- "귀족 달성까지 남은 수" 표시. 귀족 타일 탭 시 각 플레이어 진행률 오버레이.
이벤트 알림: 상대가 카드 구매/토큰 획득 시 칩이 0.4s 펄스 + 토스트 1줄. 상대 차례 중에도 내 계획을 세울 수 있도록 마켓 카드 롱프레스로 비용 부족분 하이라이트(내 토큰/보너스 대비).
2인 대전은 상대 칩 1개를 넓게(전폭) 쓰고 보너스·토큰 상세를 인라인 노출하여 탭 없이 확인.

### 비교 및 추천
| 기준 | 세로 | 가로 |
|---|---|---|
| 직장인 눈치(한 손, 지하철, 책상 아래) | **우세** | 불리(양손 필요, 화면 눈에 띔) |
| 정보 한눈 파악 | 상대는 요약+탭 필요 | **우세** |
| 비동기/턴 알림 복귀 | **우세** (한 손 짧은 세션) | 불리 |
| 카드 크기(터치) | 동일 수준 | 동일 수준(높이가 병목) |
| 구현/QA 비용 | 단일 레이아웃 | 가로 전용 + 태블릿 대응 추가 |
| 참조작 코드 재사용성 | 높음(세로 설계) | 낮음 |

**추천: 세로 전용(1순위).** 근거: (1) 타깃이 짧은 틈새·한 손 플레이를 요구, (2) 4인 최대 정보도 상대 요약 칩 + 탭 확장으로 728pt에 수용 가능(검증), (3) 가로는 높이 350pt 병목으로 얻는 이득이 상대 노출뿐이고 대신 눈치/조작 비용이 큼.
- 가로는 **1차 출시 제외**. 태블릿/데스크톱 웹은 너비 900px 이상에서 참조작처럼 2열 전환으로 대응(저비용).
- 가로 도입 시점 판단은 출시 후 지표(세션 길이, 가로 요청 피드백)로.
- 세로 사용자 편의: 확정 버튼 하단 엄지 영역, 되돌리기 1회(선택 단계 한정), 소리 없이도 진행 가능(햅틱+시각 피드백), "차례 알림" 푸시.

## 접근성 공통 규칙
- 색 단독 정보 금지: 토큰/비용 칩은 **색 + 고유 형상 아이콘 + 숫자** 병기.
- 텍스트 대비 4.5:1 이상(비용 숫자는 칩 위 외곽선/흰 바탕 처리). 최소 글자 크기 11pt, 점수/비용 숫자 14pt 이상.
- 터치 타겟 44pt 이상(iOS), 48dp(Android).

## 프로그래밍팀 연동 요청
1. 뷰포트 기준 390x844 세로 고정 레이아웃. 컴포넌트 크기를 CSS 변수(`--card-w`, `--card-h`, `--token`)로 두고 가용 높이에 따라 축소 단계(M/S) 전환할 수 있게 구조화.
2. 상대 칩 -> 하단 시트 확장 컴포넌트 (칩 tap, 시트 drag 닫기) 및 상대 이벤트 펄스 훅.
3. 마켓 카드 롱프레스 상세 + 구매 가능/부족분 표시용 상태 클래스(예: `is-affordable`, `is-short`).
4. 크리처 이미지는 WebP + 단계별 파일명 규칙 `creature_{id}_s{1-3}.webp` 지원, 애니메이션은 Lottie 또는 CSS 스프라이트 선택 가능한 로더.
5. 안전영역(`env(safe-area-inset-*)`) 적용, 하단 고정 액션바.
