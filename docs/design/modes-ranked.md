# 일반전 / 랭킹전 명세 (modes-ranked)

- 상태: 초안 v0.1 (기획팀) / 대상: 조선 스플렌더(가제)
- 전제 결정: D8(서버 권위 전환 예정), D13(멀티 전용), D6 룰 뼈대(`rules-baseline.md`, 승리 21점, 턴 제한 기본 45초)
- 수치는 모두 "가안". 실제 확정은 서버 도입 후 시뮬레이션/플레이테스트로 보정한다.

## 0. 가정

1. 현재(1단계)는 클라이언트 JS + Firebase 로비 + PeerJS P2P이며 결과 검증 수단이 없다 (§6).
2. 봇(AI) 구현은 존재한다(참조작 hard AI). 일반전 봇 채움에 재사용한다.
3. 한 판 소요 시간은 미측정. 4인 21점 기준 15~25분 추정(확인 필요: 시뮬레이션/플레이테스트).
4. 계정은 Firebase 익명 또는 소셜 로그인으로 `uid`가 있다고 가정한다. 랭킹전은 익명 계정 불가(§1.2).

## 2. 레이팅

### 2.1 방식 비교

| 방식 | 설명 | 장점 | 단점 |
|---|---|---|---|
| A. 순위 고정 점수 LP | 1위 +X, 2위 +Y, 3위 -Y, 4위 -X 등 고정값 | 이해 쉬움, 구현 단순, UI 직관 | 상대 실력 무시. 약한 상대 속 1위나 강한 상대 속 1위 같은 값. 실력 수렴 느림, 인플레 가능 |
| B. 쌍대 비교 Elo (순위 기반 다인 Elo) | 순위를 모든 쌍의 승/패로 분해해 Elo 기대값과 비교 | 상대 실력 반영, 구현 간단(수식 한 줄), 제로섬이라 인플레 없음, 인원 N 일반화 | 불확실성 모델 없음(신규 판정이 느림) → K 계수 단계로 보완. 파티/팀 없는 FFA에 적합 |
| C. TrueSkill / OpenSkill 계열 | 평균 μ, 불확실성 σ를 베이지안 갱신 | 신규 수렴 가장 빠름, 순위 직접 지원 | 구현·설명 복잡(UI에 μ/σ 숨김 필요), TrueSkill은 MS 특허/상표 이슈 가능(확인 필요), OpenSkill은 라이선스 확인 필요, 서버 검증 전 단계에선 이점 낮음 |

### 2.2 추천: B. 쌍대 비교 Elo

추천 이유:
1. 4인 FFA에서 상대 실력을 반영하는 최소 복잡도 방식이다.
2. 제로섬이라 시즌 중 점수 인플레이션이 없고 검증하기 쉽다(QA가 합계 0을 불변식으로 테스트 가능).
3. 서버 권위 도입 시 서버 함수 한 개로 구현. 클라 단계(1단계)에서도 동일 함수 사용 가능.
4. 필요 시 나중에 OpenSkill로 교체 가능하도록 내부 값은 `rating`(표시용)과 `mmr`(매칭용) 필드를 분리하되, 초기에는 `mmr == rating`으로 둔다.

### 2.3 공식

N = 판의 인원(랭킹전 4).

각 플레이어 i, 상대 j ≠ i에 대해:

```
e_ij = 1 / (1 + 10 ^ ((R_j - R_i) / 400))          // i가 j를 이길 기대
s_ij = 1   (i 순위가 j보다 높음)
       0.5 (동률: 같은 rank 공유, rules-baseline B12 공동 순위)
       0   (i 순위가 j보다 낮음)

S_i = (1 / (N-1)) * Σ_j s_ij
E_i = (1 / (N-1)) * Σ_j e_ij

ΔR_i = round( K_i * (S_i - E_i) )
```

- 불변식: `Σ_i (S_i - E_i) = 0` 이므로 반올림 전 ΔR 합은 0. 반올림으로 생긴 합 오차(±1~2)는 허용(제로섬 완전 보장 불필요). 합 오차는 검증 테스트에서 |Σ ΔR| ≤ N 으로 확인.
- 순위 정의: rules-baseline §2.7 `getRanking` (점수 → 승급 횟수 많음 → 필드 카드 적음 → 동률 공유).
- 이탈자: §5.3.

### 2.4 파라미터 (가안)

| 항목 | 값 | 비고 |
|---|---|---|
| 초기 rating | 1000 | 배치고사 후 시작 티어 결정(§3.4) |
| K (배치고사 5판) | 96 | 빠른 수렴 |
| K (6~30판) | 64 | |
| K (31판 이후) | 48 | |
| K (정3품 이상 구간) | 40 | 상위권 변동 완화 |
| rating 하한 | 0 | 0 미만 불가 |
| 표시 | 정수 "품계 점수(RP)" | 숨은 mmr 분리는 Q2 |
| 1위 최소 이득 | +8 | 모든 상대가 훨씬 약해도 1위면 최소 +8 (이탈 방지 설계 아님, 승리 동기 보장) |
| 4위 최소 손실 | -8 | 모든 상대가 훨씬 강해도 4위면 최소 -8 → 4위 감점 0으로 수렴 방지 |

(1위 최소 이득/4위 최소 손실은 제로섬을 약간 깨므로 합 오차 허용 범위를 넘으면 제한 여부 QA 재검토. 열린 질문 Q3.)

### 2.5 예시 계산 (4인, K=64)

**예시 1. 전원 1500 동급**

모든 쌍 e = 0.5 → E_i = 0.5.

| 순위 | 플레이어 | S | E | ΔR |
|---|---|---|---|---|
| 1위 | P1 | 1.000 | 0.5 | +32 |
| 2위 | P2 | 0.667 | 0.5 | +11 |
| 3위 | P3 | 0.333 | 0.5 | -11 |
| 4위 | P4 | 0.000 | 0.5 | -32 |

합계 = 0.

**예시 2. 실력 차 존재**

A=1700, B=1500, C=1500, D=1300. 결과 순위: 1위 B, 2위 A, 3위 D, 4위 C.

사전 계산 (e 값, 차 200 → 0.7597/0.2403, 차 400 → 0.9091/0.0909):

- E_A = (0.7597 + 0.7597 + 0.9091) / 3 = 0.8095
- E_B = (0.2403 + 0.5 + 0.7597) / 3 = 0.5000
- E_C = 0.5000 (B와 동일)
- E_D = (0.0909 + 0.2403 + 0.2403) / 3 = 0.1905

실제 결과 S: A는 D, C를 이기고 B에게 짐 → 2/3 = 0.667. B = 1.000. C = 0.000. D는 C만 이김 = 0.333.

| 순위 | 플레이어 | rating | S | E | ΔR |
|---|---|---|---|---|---|
| 1위 | B | 1500 | 1.000 | 0.5000 | +32 |
| 2위 | A | 1700 | 0.667 | 0.8095 | -9 |
| 3위 | D | 1300 | 0.333 | 0.1905 | +9 |
| 4위 | C | 1500 | 0.000 | 0.5000 | -32 |

합계 = 0. 해석: 강자 A가 2위로 -9, 약자 D가 3위로 +9. 상대 실력이 반영된다. (§2.4의 최소 이득/손실 규칙은 이 예시에서 발동하지 않음.)

**예시 3. 동률**

전원 1500, 1위·2위 공동(점수/승급/필드 수 전부 동일), 3위 P3, 4위 P4. 공동 1위 쌍은 s=0.5.
- P1: S = (0.5 + 1 + 1)/3 = 0.833 → ΔR = 64 × 0.333 = +21
- P2: 동일 +21
- P3: S = (0 + 0 + 1)/3 = 0.333 → -11
- P4: S = 0 → -32
합계 = -1 (반올림 오차, 허용).

### 3.2 승급 / 강등

- 승급: RP가 상위 구간 하한 이상이 되면 즉시 승급 (판 종료 결과 화면에서 연출).
- 강등: RP가 현재 단계 하한 미만으로 내려가면 강등 후보. 아래 보호 규칙 적용.

### 3.3 보호

1. 승급 직후 방패: 단계 승급 후 3판간 강등 없음. 이 기간 RP는 현재 단계 하한 아래로 내려가도 표시 RP를 하한으로 고정(`rp = max(rp, floor)`)하되 내부 rating은 계속 갱신. 3판 후 내부 rating이 하한 미만이면 강등.
2. 품 경계 완충: 품(예: 7품 → 8품) 경계를 넘어 강등될 때는 하한 -50까지 허용 후 강등. 예: 종7품(1000~)에서 정8품(900대)으로 내려가려면 RP < 950이어야 한다. 같은 품 안의 정→종 강등은 완충 없음.
3. 종9품은 강등 없음. rating 0 하한.
4. 시즌 초 첫 5판(§4.2)은 강등 없음.

### 3.4 배치고사

- 판수: 5판 (랭킹전 해금 후 첫 5판). 일반전 판은 불산입.
- K = 96 (§2.4). 매 판 결과 계산.
- 배치 중 표시: 티어 대신 "배치 3/5". 중간 티어 비공개.
- 배치 후 시작 티어 상한: 종5품(RP 1499). 배치만으로 정5품 이상 불가(최소 이상 안정성 확인 전 상위 진입 방지).
- 배치 결과 rating = 1000 + Σ ΔR (하한 0, 상한 1499 클램프).
- 시즌 리셋 후에는 부분 배치 2판(§4.2).

## 4. 시즌

### 4.1 기간

- 12주(84일). 월요일 04:00 KST 시작/종료 가안. 시즌 종료 3일 전 알림.
- 시즌 번호 `S1, S2 ...`. 시즌 0 = 1단계 비공식 시범(§6).

### 4.2 리셋 규칙 (소프트 리셋)

```
rating_new = 1000 + (rating_old - 1000) * 0.5
```

- 예: 2200 → 1600, 1000 → 1000, 800 → 900.
- 리셋 후 부분 배치 2판 (K=96). 첫 2판 강등 없음.
- 티어는 새 rating으로 재계산. 시즌 최고 티어는 `bestTier`로 기록 후 보상에 사용.
- 시즌 중간 이전 시즌 정보는 프로필 `seasonHistory`에 보관.

### 4.3 보상 (코스메틱만, 재화 보상 최소)

원칙: 룰·확률·카드 성능에 영향 없음 (monetization.md 원칙과 동일). 시즌 최고 티어(`bestTier`) 기준.

| 최고 티어 | 보상 |
|---|---|
| 배치 완료 | 프로필 테두리 "시즌 참여" |
| 종8품 이상 | 시즌 한정 이모트 1종 |
| 종6품 이상 | 시즌 한정 아바타 테두리 (색상 단계형) |
| 종4품 이상 | 시즌 한정 카드 프레임 |
| 정3품(당상) 이상 | 시즌 한정 구슬 스킨 |
| 정1품 | 시즌 한정 칭호 "S{n} 정1품" |
| 영의정 (서버 검증 후) | 칭호 "S{n} 영의정" + 전용 프로필 배경 |
| 임금 (서버 검증 후) | 칭호 "S{n} 임금" + 전용 아바타 효과 + 게임판 테마 |

- 이전 시즌 한정 보상은 해당 시즌에만 획득. 이후 상점 판매 안 함(또는 후속 시즌 재출시 여부 Q6).
- 보상 지급은 시즌 종료 직후 우편함(서버 검증 후).

## 5. 이탈 / 닷지 / 타임아웃

### 5.1 일반전

- 매칭 후 수락 단계 없음(자동 입장). 닷지 개념 없음.
- 이탈 시 봇이 즉시 대체. 페널티 없음. 단, 10분 내 3회 이상 이탈하면 일반전 큐 5분 제한.
- 타임아웃: 턴 제한 초과 시 자동 행동(§5.4). 연속 3회 타임아웃이면 AFK로 보고 봇 대체.

### 5.2 랭킹전

**닷지 (매칭 수락 단계)**: 랭킹전은 매칭 성사 후 15초 "수락" 단계를 둔다. 수락하지 않거나 시간 초과 시 닷지.

| 24시간 내 닷지 횟수 | 큐 제한 | RP 페널티 |
|---|---|---|
| 1회 | 5분 | 없음 |
| 2회 | 30분 | 없음 |
| 3회 이상 | 2시간 | -10 RP |

- 수락한 나머지 플레이어는 재큐 시 우선권(대기 시간 승계) 부여.

**게임 중 이탈**: 연결 끊김 또는 앱 종료.

| 단계 | 처리 |
|---|---|
| 재접속 유예 | 연결 끊김 후 60초 동안 좌석 유지. 이 동안 턴이 오면 타임아웃 자동 행동 |
| 봇 대체 | 60초 경과 또는 연속 3회 타임아웃 시 봇이 좌석을 넘겨받아 판 진행 (남은 3명의 게임 보호) |
| 재접속 | 봇 대체 전: 즉시 복귀. 봇 대체 후: 관전자 모드로 복귀(좌석 회수 불가). 이 판 결과는 §5.3 이탈 처리 |
| 즉시 포기 | 메뉴의 "항복" 버튼. 이탈 처리(§5.3). 확인 대화상자 필수 |

### 5.3 이탈 시 점수 처리

원칙: 이탈자는 해당 판에서 **항상 최하위 순위**로 처리하고, 봇이 남은 판을 진행하되 봇의 성과가 이탈자의 순위에 영향 없음. 남은 플레이어끼리는 실제 게임 결과 순위로 계산.

1. 이탈자 1명:
   - 이탈자 순위 = 4위(최하위 고정). 다른 3명은 서로 간 실제 순위를 1~3위로 하고 이탈자 대비 모두 승리.
   - 이탈자 ΔR = §2.3 정상 계산(4위 취급) + 추가 페널티 -10 RP.
   - 나머지 3명은 정상 계산. 이탈자 좌석이 봇이어도 나머지 3명의 이득/손실은 감쇠 없이 정상 적용.
2. 이탈자 2명 이상:
   - 이탈 시점이 늦은 사람이 높은 순위(3위 → 4위 순). 같은 시점은 동률.
   - 남은 플레이어는 정상 계산.
3. 조기 무효: 게임 시작 후 **라운드 3 종료 전**(모든 플레이어가 3턴을 마치기 전)에 이탈이 발생하면 판 무효. 남은 플레이어 RP 변동 0, 이탈자는 -15 RP + 큐 제한 10분. 무효 판은 배치고사 판수에 불산입.
4. 이탈자의 이탈 이력(`leaveCount`)을 7일 롤링으로 기록. 7일 내 3회 이상이면 랭킹전 큐 24시간 제한.

### 5.4 타임아웃 자동 행동

참조작 B1, B2(타임아웃 미작동/반환 건너뜀)를 신작에 이식하지 않는다.

- 행동 페이즈 타임아웃: 가능한 합법 행동 중 "패스(`pass`)"가 허용되지 않으므로 서버가 자동으로 `takeBalls`(가져올 수 있는 3종, 재고 많은 순) 실행. 불가 시 `reserve`는 하지 않음. 다 불가하면 `pass`.
- 반환 페이즈 타임아웃: 보유 개수가 많은 색 순으로 초과분을 자동 반환 (여의주 최후).
- 승급 페이즈 타임아웃: `skipEvolve`.
- 타임아웃 카운트는 연속 타임아웃 수로 센다. 사람의 정상 행동이 1회 있으면 리셋.
- 타이머는 서버 권위(D8 이후)에서 서버가 관리. 클라 표시 타이머는 서버 시각과 동기.
- 타임아웃 자체에 RP 페널티는 없다(이탈 처리와 분리). 단, 3연속이면 AFK → 봇 대체 → §5.3 이탈로 처리.

### 5.5 서버 장애 / 무효 처리

- 서버 또는 다수 클라 장애로 판 진행 불가 시 무효 처리. RP 변동 0, 페널티 없음.

## 6. 공정성 전제 및 단계적 도입

현 구조(클라 JS + P2P, 서버 비권위)에서는 클라이언트가 결과를 조작해 레이팅을 올릴 수 있다. 참조작 B3(비차례 액션 주입), B4(비공개 덱 노출) 구조가 그대로 남아 있다. 따라서 랭킹전을 "공식"으로 인정하려면 서버 검증이 선결 조건이다.

### 6.1 1단계: 비공식 랭크 ("시범 시즌", 시즌 0)

| 항목 | 내용 |
|---|---|
| 서버 | 현 구조 그대로 (Firebase 로비 + PeerJS) |
| 결과 기록 | 호스트 클라가 결과를 Firebase에 기록, 참가자 전원이 동일 결과를 보고해 일치할 때만 반영(합의 방식). 불일치 시 판 무효 |
| 표시 | 모든 곳에 "시범 랭크(비공식)" 라벨. 티어 배지에 점선 테두리 |
| 영의정/임금 | 비활성 |
| 보상 | 참여 기록 외 코스메틱 보상 없음 (조작된 보상 방지). 공식 시즌 시작 시 별도 "시범 시즌 참여" 테두리 일괄 지급 |
| 리더보드 | 없음 (또는 "비공식" 라벨의 친구 간 순위만) |
| 이월 | 시즌 0의 rating은 공식 시즌 1에 반영하지 않고 초기화. 단 최고 티어는 보상 참고용 기록 |
| 한계 | 합의 방식은 4인 중 3명이 공모하면 우회 가능. 보상이 없으므로 허용 가능한 리스크로 판단 |

완화책(프로그래밍팀 요청): 결과 기록 시 참가자 전원 uid와 `seed`, 액션 로그를 같이 저장해 사후 서버 재현 검증이 가능하게 함(락스텝 결정론 활용). 재현 검증은 2단계 전에 오프라인 배치로 시도 가능.

### 6.2 2단계: 서버 검증 후 공식

D8(서버 권위) 전제.

| 항목 | 내용 |
|---|---|
| 서버 역할 | 룰 엔진 서버 실행, 액션 검증(차례/합법성), 비공개 정보 은닉, 타이머 관리, 결과 확정 |
| 레이팅 | 서버만 `rating` 쓰기. 클라는 읽기 전용 (보안 규칙으로 강제) |
| 결과 | 서버가 확정한 `ranking`으로 §2 계산 |
| 보상 | 시즌 종료 시 서버가 지급 |
| 영의정/임금 | 활성 |
| 리더보드 | 공식 |
| 이전 | 시즌 0 → 1 사이에 서버 도입 완료 후 시즌 1 시작 |

**공식 시즌 시작 조건**: ① 서버 권위 구현 ② 비공개 정보 은닉 확인 ③ 타임아웃/반환/이탈 처리 QA 통과 ④ 레이팅 계산 서버 단위 테스트 통과(합계 0 불변식). 이 4개가 충족되기 전에는 "공식"이라는 표현을 쓰지 않는다.

### 7.2 UI 요구사항

1. **모드 선택 화면** (홈): 일반전 / 랭킹전 / 친구 방 카드 3개. 랭킹전 카드는 미해금 시 잠금 아이콘과 잔여 조건("레벨 10 / 일반전 10판") 표시. 인원 선택(2/3/4)은 일반전 시작 전 하단 시트.
2. **티어 배지**: 홈 프로필, 매칭 큐 화면, 인게임 플레이어 패널(작게), 결과 화면에 표시. 배치 중에는 "?" 배지와 "3/5". 1단계는 "시범" 리본.
3. **랭킹전 큐 화면**: 경과 시간, 현재 허용 범위 확대 문구, 취소 버튼(수락 전 취소는 페널티 없음). 매칭 성사 후 15초 수락 화면(4명 수락 상태 표시).
4. **결과 화면**: 순위 1~4위와 각자 점수, 승급/타이브레이커 표기. 본인 RP 변동 애니메이션(예: 1532 → 1564, +32 숫자 올라감), 티어 바 진행. 승급·강등 연출. 이탈자는 "이탈" 표시. 무효 판은 "판 무효, 점수 변동 없음". 일반전/친구 방은 점수 변동 대신 경험치/보상.
5. **시즌 화면**: 남은 기간, 시즌 최고 티어, 보상 미리보기 목록.
6. **재접속**: 끊김 시 "재접속 중 (남은 유예 45초)" 배너.
7. **이탈 경고**: 랭킹전 중 나가기/항복 시 페널티 문구 포함 확인창.
8. 접근성: 티어는 색뿐 아니라 숫자와 모양으로 구분.

## 8. 타팀 요청사항

- 프로그래밍팀:
  - 레이팅 함수 `calcRatingDelta(players, K)` 순수 함수로 구현, 단위 테스트(R-01~R-04, R-14) 포함.
