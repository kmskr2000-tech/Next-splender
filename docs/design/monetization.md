# 유료화 설계 검토 (monetization)

- 상태: 검토 초안 v0.1 (기획팀). 구현 확정 문서 아님.
- 법률/약관 수치는 기획팀 일반 지식 기준이며 **법무 검토 전 확정 금지**. 확실치 않은 항목은 "확인 필요"로 표기.
- 가격은 모두 가안(원화, 부가세 포함 가정). 시세 검증 필요.
- 전제: D8 서버 권위 전환, D13 멀티 전용, D12 도트 그래픽. 결제/인벤토리는 서버 없이는 안전하게 운영 불가(§5.5).

## 1. 원칙

1. **Pay-to-Win 금지.** 유료 아이템은 룰, 확률(덱 셔플 포함), 카드 성능(비용·점수·보너스·승급 조건), 타이머, 매칭에 영향을 주지 않는다.
2. **코스메틱 중심.** 판매 대상은 외형과 연출뿐. 외형이 정보 가독성을 해치지 않는다.
3. **정보 가독성 보호.** 스킨이 바꿀 수 없는 요소: 구슬 색(오방색 hex + 한자 표기, roster-korea §2), 카드 비용 아이콘/점수 숫자/보너스 색 표시, 승급 가능 표시. 색각 이상 대응(한자 병기)은 스킨에서도 유지.
4. **무료로도 즐길 수 있음.** 모든 게임플레이 콘텐츠(카드, 모드)는 무료. 무료 보상으로 일부 코스메틱을 얻는다.
5. **확률형 최소화.** 직접 구매 우선. 확률형이 필요하면 확률을 공개한다(§3).
6. **IP 존중.** 실존 인물 스킨(복식)은 존중 묘사 (roster-korea §8). 현대 드라마/웹툰 설정 차용 금지. 후손/유족 이슈가 없는 역사 인물 위주로 한다(확인 필요: 인격권/초상권 관련은 고인에 대해 별도 법리 존재, 법무 검토).
7. **어린이·청소년 보호.** 결제 한도, 법정대리인 동의 흐름을 설계 단계부터 반영 (§3.4).

## 2. 상품군

우선순위: P0 = MVP 포함, P1 = 결제 연동 단계, P2 = 이후.
제작 난이도: 낮음 = 도트 생성기+소량 후보정으로 대량 제작 가능 / 중 = 라인별 수작업 일부 필요 / 높음 = 애니메이션 또는 개별 기획 필요.
도트 생성기 가정: 팀이 보유한 도트 생성기(파이프라인)로 카드 스프라이트를 라인별 대량 생성할 수 있다고 가정(확인 필요: 아트팀 파이프라인 실제 처리량).

| 상품군 | 설명 | 우선순위 | 제작 난이도 | 대량 제작 | 가격대 가안 |
|---|---|---|---|---|---|
| 인물 스킨 | 라인별 대체 복식(예: 이순신 평상복, 전투복 / 계절·명절 테마: 설날 한복, 추석, 단오, 겨울). 승급 단계 3장(T1~T3) 세트로 판매 | P1 | 중~높음 (라인 36개 x 단계 2~3, 세트당 최대 3스프라이트) | 부분 가능: 팔레트/의상 베이스 교체형은 생성기 가능. 얼굴·소품은 후보정 | 라인 세트 1,500~3,300원, 명절 번들(6라인) 7,900원 |
| 아바타/프로필 테두리 | 홈·인게임 플레이어 패널 테두리 | P0 | 낮음 | 가능 (패턴 합성) | 무료 보상 다수 / 유료 800~1,500원 |

| 게임판(테이블) 테마 | 배경과 테이블 매트 (사랑방, 궁궐, 장터, 설경, 달밤) | P1 | 중 (큰 1장 + 타일 반복) | 가능 (AI 초안+후보정) | 1,500~3,300원 |
| 성장 연출 이펙트 | 승급(성장) 시 이펙트 (벚꽃, 용 승천 라인 연출, 불꽃놀이) | P2 | 높음 (애니메이션+사운드) | 낮음 | 1,500~3,300원 |
| 이모트/스티커 | 도트 감정 표현 (한국형: 엄지척, 호랑이 울음, 도깨비 방망이) | P0 | 낮음 | 가능 | 1,000~2,000원/팩(6~8종). 무료 기본 팩 포함 |
| 시즌 패스 | 무료/유료 두 트랙, 12주 시즌에 맞춤(modes-ranked 시즌과 동기 가능) | P2 | 중 (보상 목록 기획 중심) | 해당 없음 | 유료 트랙 4,900원 (가안) |
| 칭호 | 프로필 문구 ("삼도수군통제사", "을지문덕 팬") | P0 | 낮음 (텍스트) | 가능 | 무료 업적 중심. 유료는 거의 없음 |

### 2.1 우선 제작 순서 제안

1. P0: 프로필 테두리, 카드 프레임 1~2종, 기본 이모트 팩, 칭호 (업적/시즌 보상으로 무료 제공 → 상점 UI 검증).
2. P1: 인물 스킨 시범 3라인(이순신, 신사임당, 도깨비 등 가독성 좋은 라인 우선) + 구슬 스킨 1세트 + 게임판 테마 2종.
3. P2: 성장 이펙트, 시즌 패스, 명절 번들.

### 2.2 판매하지 않는 것 (명시)

- 카드 개별 구매/자원/토큰 보너스/타이머 연장/턴 제한 면제/매칭 우선권/시즌 점수 부스터.
- 랭킹 점수(RP) 직접 판매. 시즌 패스에도 RP 보너스는 넣지 않는다.
- 유료 한정 카드(룰 영향 가능). 카드는 전부 무료로 동일하게 등장한다.

## 3. 재화 구조 및 규제

### 3.1 재화

권장: **유료 재화와 무료 재화를 분리.**

| 재화 | 이름(가안) | 획득 | 용도 |
|---|---|---|---|
| 유료 재화 | 엽전 | 현금 구매(1엽전 = 10원 가안), 유료 시즌 패스 일부 | 모든 상점 아이템 구매 가능 |
| 무료 재화 | 푼(가안) | 플레이 보상, 업적, 시즌 패스 무료 트랙 | 기본/일부 코스메틱만 구매 가능 |

- 분리 이유: 법적·회계적 책임 분리(무상 재화는 환불·청약철회 대상에서 분리, 확인 필요), 환불 처리 단순화, 유저 인식 명확.
- 유료 재화 사용 순서: 무료 재화 우선 소모는 적용하지 않고, 상품별 사용 재화가 상품 정보에 명시된다(혼동 방지).
- 시즌 한정 상품은 유료 재화 전용으로 하더라도, 시즌 패스 무료 트랙에서 일부 한정품을 획득할 수 있게 해 "과금 필수"로 보이지 않게 한다.
- 유료 재화 유효기간: 두지 않는 것을 권장(국내 상품권/선불 규정과 소멸시효 이슈, 확인 필요).
- 환불: 미사용 유료 재화는 전자상거래법상 청약철회 7일(법 조항 확인 필요) 정책 반영. 사용분 환불 제한은 약관 명시(확인 필요).

### 3.2 직접 구매 vs 뽑기

권장: **직접 구매 중심. 뽑기(확률형 아이템) 도입하지 않음.**

| 방식 | 장점 | 단점 |
|---|---|---|
| 직접 구매 | 규제 리스크 낮음, 신뢰 높음, 가격 설명 쉬움 | 매출 상한 낮음, 아이템 소진 후 신규 제작 필요 |
| 뽑기(가챠) | 단가 대비 매출 가능성 높음 | 규제·평판 리스크, 청소년 이슈, 확률 공개·관리 비용, 컴플리트 가챠 금지 이슈(확인 필요) |

- 시즌 패스·이벤트 보상은 확정형(트랙 도달 시 지급).
- 부득이 랜덤 요소(예: 상자)를 넣는 경우 §3.3 준수 + 중복 보상 처리(분해/환급) 설계 필요. 현 로드맵에서는 계획 없음.

### 3.3 규제 리스크 (한국)

| 항목 | 내용 | 확실도 |
|---|---|---|
| 게임산업법 확률형 아이템 정보 공개 | 2024.3.22 시행으로 알려짐. 게임 내에서 유료로 판매/획득되는 확률형 아이템의 종류별 확률 정보를 공개해야 함. 거짓 표시 시 제재(시정권고·명령, 처벌) | 시행 시점/대상 범위의 세부는 **확인 필요** |

| 전자상거래 표시·광고 (공정위) | 확률 표시/광고 규제가 별도로 시행(시행 시기 포함) | **확인 필요** |
| 미성년자 결제 | 법정대리인 동의 없는 미성년자 법률행위는 취소 가능(민법) | 일반 원칙은 확실, 게임 적용 절차는 **확인 필요** |

권고:
1. 확률형 아이템 미도입(이 문서 전체 방침).
2. 도입 시 확률 표기(구매 화면 + 도움말 + 웹), 수치 변경 시 공지·기록 보관, 법무 검토 선행.
3. 청소년 결제 보호: 연령 확인(최소 생년/성인 인증 연동), 미성년 계정 월 결제 한도(수치는 법적 요구 확인 후 확정; 이 문서에서는 가안 월 7만원 이하, **확인 필요**), 법정대리인 동의 및 결제 알림.
4. 구매 전 최종 확인 화면 (가격·재화·환불 규정). 구매 내역/영수증 조회.
5. 모든 상품에 "무엇이 바뀌는가(외형만)"를 명시해 PTW 오해 방지.
6. 법무 자문 후 출시. 현재 문서의 법 조항은 확정 근거로 쓰지 말 것.

### 3.4 청소년 보호 흐름 (설계 요구)

- 가입 시 연령대 입력(생년). 만 14세 미만은 법정대리인 동의 없이는 결제 기능 비활성(확인 필요: 서비스 가입 가능 연령 정책).
- 미성년 판정 계정은 결제 한도와 알림 적용.
- 환불/문의 창구 고지.

## 4. 결제 경로 비교

| 항목 | 웹 (PG) | 앱 (Capacitor 래핑 + 인앱결제) |
|---|---|---|
| 도입 속도 | 빠름 (웹 우선 출시 가능) | 느림 (빌드, 스토어 심사) |
| 수수료 | PG 약 3% 전후 (확인 필요) + 부가세 | 스토어 약 15~30% (규모/프로그램별 상이, 확인 필요) |
| 사용자 마찰 | 결제 수단 입력 필요 | 스토어 계정 결제로 간편 |
| 정책 리스크 | 낮음 (웹은 자유) | 디지털 재화는 스토어 인앱결제 정책 적용. 앱 내 외부 결제 안내/유도는 정책 제한 (한국은 제3자 결제 허용 법령이 있으나 수수료·조건 확인 필요) |
| 환불 | 자체 처리(PG 취소) | 스토어 환불 정책에 종속 |
| 구현 | PG SDK + 서버 결제 검증(webhook) | Capacitor 플러그인(구글/애플 인앱) + 서버 영수증 검증 |
| 계정 연동 | 자체 계정 필요 | 자체 계정 + 스토어 영수증 연결 |
| D4(스마트폰 전용 웹) 정합 | 정합 | 별도 분배 채널(결정 필요) |

권고:
1. 1차 웹(PG) 결제: 수수료와 심사 부담이 적어 초기 검증에 적합.
2. 앱 출시 시점에 인앱결제 병행. 두 경로 동일 카탈로그/인벤토리를 쓰도록 서버 구현.
3. 어느 경로든 구매 확정은 서버에서만(§5.5).
4. 앱 래핑 전환 여부는 D4와 별개로 디렉터 결정 필요(열린 질문 Q3).

- `target.line_id`: 라인 단위 스킨. `card_ids`는 해당 라인의 카드 id 전체 (roster-korea.json lines). 단일 카드 스킨은 `card_ids` 1개.
- `slot`: 같은 슬롯에 한 번에 하나만 장착. 카드 스킨의 슬롯은 `cardSkin:{line_id}`로 라인별 슬롯 (한 라인에 스킨 한 개).
- `rarity`: 표시 용도만. 확률과 무관.
- `gameplayEffect`: 항상 "none" (서버/CI가 카탈로그 검증 시 필수 확인).

### 5.3 렌더링 훅 (스킨 장착 시 스프라이트 경로 치환)

규칙:

```
기본: assets/cards/{cardId}.png            (프로그래밍팀 기존 경로 확인 필요)
스킨: assets/skins/{skinId}/{cardId}.png
```

해결 순서(resolveCardSprite(cardId, ownerEquipped)):
1. 카드 id에서 `line_id` 조회(roster 데이터).
2. `ownerEquipped.cardSkins[line_id]` 값이 있고 카탈로그에서 유효하면 `skinId` 확보.
3. 스킨 경로 `assets/skins/{skinId}/{cardId}.png` 존재(매니페스트 `skin.files` 기준)하면 그 경로 사용.
4. 없으면 기본 스프라이트로 폴백 (스킨이 일부 단계만 제공될 때 포함).
- 로드 실패 시 폴백 후 오류 로그만 남기고 게임 진행에 영향 없음.
- 스킨 매니페스트: `assets/skins/{skinId}/manifest.json` (`{cardIds[], size, version}`). 크기/앵커 동일 규격 강제(레이아웃 불변).
- 다른 슬롯 훅: `avatarFrame`, `cardFrame`, `orbSkin`, `tableTheme`, `evolveFx`는 id → 에셋 경로 맵을 카탈로그에서 해석. 구슬 스킨은 색 코드 키(`monster/super/hyper/heal/quick/master`)별 파일 규약 `assets/orbs/{orbSkinId}/{colorKey}.png`.
- 사전 로드: 게임 시작 전 로딩 화면에서 참가 4명의 장착 스킨 에셋만 프리로드. 총 용량 상한(가안 2MB)을 넘는 경우 우선순위로 자기 스킨 → 상대 스킨 순서. 로드 실패 시 폴백.
- 승급 이펙트는 승급 시킨 플레이어의 `evolveFx` 사용 (모두에게 재생).

### 5.4 상대에게 내 스킨이 보이는지 (동기화 필드)

원칙: 장착 정보는 외형일 뿐 룰 상태와 분리. 게임 시작 시 좌석 정보에 포함하여 서버가 검증된 값만 방송.

좌석 동기화 필드(`SeatCosmetics`):

```json
{
  "uid": "string",
  "avatarFrame": "id|null",
  "title": "id|null",
  "tierId": "string",
  "cardFrame": "id|null",
  "orbSkin": "id|null",
  "evolveFx": "id|null",
  "cardSkins": { "line_id": "skin_id" },
  "emotes": ["id", "..."]
}
```

| 요소 | 동기화 | 설명 |
|---|---|---|
| 카드 스킨 | 소유자(필드 카드 주인) 기준 | 내가 구매한 카드는 내 필드에서 내 스킨. 공개 테이블/상대 필드 카드는 해당 소유자 기준. 공개 테이블 카드는 기본 스킨 |
| 카드 프레임, 구슬 스킨, 승급 이펙트, 아바타 프레임, 칭호, 티어 | 모두에게 보임 | 소유자 기준 표시 |
| 게임판 테마 | **로컬 전용**(각자 자기 화면). 서로 다른 테마여도 룰/정보 동일 | 동기화 불필요 |
| 이모트 | 전체 전송 | 이벤트 `emote {id}` 전송, 서버가 장착/소유 확인 |
- 설정 옵션: "상대 스킨 표시 끄기"(성능/가독성/데이터 절약)를 제공. 끄면 상대는 기본 외형으로 렌더(로컬 설정, 동기화 불필요).
- 공개 정보 보호: 예약 카드(비공개)의 스킨 정보로 카드 정체가 드러나지 않게 한다. 예약 카드는 뒷면 렌더 시 스킨 id 전송 금지.
- 서버 권위 이전(D8) 전 1단계(P2P)에서는 클라 자가 신고 값이므로 "표시 전용"으로만 사용 (치팅해도 룰 영향 없음). 단 소유 검증 없는 스킨 표시는 유료 상품 회피(무임승차)가 되므로 결제 도입 전에 서버 검증 필수.

### 5.5 서버 검증 필요 지점

| 지점 | 이유 |
|---|---|
| 결제 승인 / 영수증 검증 | PG webhook 및 스토어 영수증을 서버에서 검증. 클라 신고 불신 |
| 재화 잔액 증감 | 서버만 기록. 이중 지급·롤백 처리 |
| 구매(상점) 트랜잭션 | 멱등 키(orderId)로 중복 지급 방지 |
| 소유권 확인 | 장착 요청마다 서버가 인벤토리 확인 |
| 장착 값 방송 | 게임 시작 시 서버가 검증된 `SeatCosmetics`만 좌석 정보로 전달 |
| 보상 지급 | 시즌 보상, 업적 보상, 시즌 패스 단계 서버가 판정 |
| 시즌 패스 XP | 서버가 판 결과 기준 계산 (클라 신고 XP 금지) |
| 환불 / 회수 | 환불 시 아이템 회수·재화 차감 처리 |
| 한정 판매 기간 | 서버 시각 기준 |
| 카탈로그 무결성 | `gameplayEffect:none` 및 가격 위변조 방지 (서버가 카탈로그 소유) |

선행 의존: D8 서버 권위. 서버 없이 Firebase 클라 쓰기만으로는 재화/소유권을 안전하게 운영할 수 없다. 최소 Cloud Functions 등 서버 코드 필요(구현 방식은 프로그래밍팀 결정).

## 7. 핵심 지표 가안 (참고)

- 가입 대비 유료 전환율, ARPPU는 목표치 설정하지 않음(타깃 모수 미정).
- 모니터링: 시즌 패스 완주율, 무료 코스메틱 장착률, 상점 방문 대비 구매 전환, 환불률, 청소년 결제 비율.

## 8. 타팀 요청사항

- 프로그래밍팀: 카탈로그/인벤토리 스키마 구현, `resolveCardSprite` 훅, 폴백, 프리로드, 서버 소유권 검증 및 결제 검증(D8 연계), 멱등 구매 처리.
- 아트팀: P0 코스메틱 에셋 규격(프레임 9-slice, 이모트 크기), 스킨 스프라이트 규격(카드와 동일 크기/앵커), 시범 스킨 3라인 도트 생성기 파이프라인 처리량 검토, 상점 UI 와이어프레임.
- 사운드팀: 구매/장착 SFX, 성장 이펙트 사운드(P2).
- QA팀: 스킨 장착 시 룰 상태 불변, 폴백, 상대 화면 동기화, 예약 카드 정보 노출 없음, 결제 멱등/환불 시나리오(2단계).
- 법무(디렉터 경유): §3.3 확인 필요 항목 전수 검토, 약관/개인정보 처리방침, 등급분류.
